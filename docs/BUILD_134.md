# Build 134: avoid duplicate bytes after a partial filter stream error

Unreleased 0.3.104. A buffered YouTube JSON response may be passed through unchanged if its body cannot be safely rewritten. Previously the original-byte flush used a for-loop and cleared the buffer only after all writes succeeded. If a later filter.write failed, the fallback could retry the full buffer, duplicating chunks already accepted by the browser. The stream now tracks which chunks it has attempted before each write, so fallback attempts never replay earlier chunks. Tests simulate a write failure after accepting a chunk, and verify each original chunk is delivered exactly once. A failed write before accepting bytes may still cause an incomplete stream; Firefox error handling and actual playback validation remain pending. No release or GitHub Actions.
