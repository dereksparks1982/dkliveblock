# Build 125: do not mask server-side playback refusals in feeds

Unreleased 0.3.95. Earlier safety checks preserved explicit playability refusal only in player JSON, but browse/next/playlist responses used a separate feed scanner. A response containing `playabilityStatus` other than OK or a structured API error now remains completely unmodified in that scanner, even when it also contains advertising entries. This avoids treating removal of an ad marker as successful authorization or playback restoration. Ordinary authorized feed and playlist responses remain eligible for ad-only filtering. Tests cover denied statuses, structured errors, player response integration and an authorized feed. Full Linux and Firefox acceptance still pending; no Actions or user installation request.
